CORE OOP PILLARS

07 Áp Dụng Triệt Để 4 Tính Chất OOP

1. Tính Đóng Gói (Encapsulation)

Che giấu toàn bộ trường dữ liệu bằng private. Ngăn chặn sửa đổi trực tiếp availableQuantity hay status từ bên ngoài mà không thông qua các phương thức nghiệp vụ có kiểm tra điều kiện.

2. Tính Kế Thừa (Inheritance)

Tái sử dụng mã nguồn tối đa qua 3 cây kế thừa chính: User → Reader/Librarian; BaseRepository<T> → các Repository cụ thể; và LibraryException → 12 lớp ngoại lệ con.

3. Tính Trừu Tượng (Abstraction)

Định nghĩa khung hành vi chuẩn qua các lớp trừu tượng User, Reader, BaseMenu và hai Interface cốt lõi là Borrowable và FinePolicy.

4. Tính Đa Hình (Polymorphism)

Cùng một lời gọi reader.getMaxBorrowBooks() hay policy.calculateFine(...) nhưng hành vi tự động biến đổi theo đối tượng thực tế lúc runtime.

09 Strategy Pattern Cho Chính Sách Tính Phạt

src/service/FinePolicy.java
Interface FinePolicy
NormalStudent
Priority & Lecturer
package service;

public interface FinePolicy {
    /**
     * Tính tiền phạt dựa trên số ngày trễ và số sách
     */
    double calculateFine(long overdueDays, int totalBooks);
}
public class NormalStudentFinePolicy implements FinePolicy {
    private static final double RATE_PER_DAY = 5000.0;

    @Override
    public double calculateFine(long overdueDays, int books) {
        if (overdueDays <= 0 || books <= 0) return 0.0;
        return overdueDays * books * RATE_PER_DAY;
    }
}
// PriorityStudentFinePolicy: 3.000 VNĐ/cuốn/ngày
public class PriorityStudentFinePolicy implements FinePolicy {
    public double calculateFine(long days, int books) {
        return days <= 0 ? 0 : days * books * 3000.0;
    }
}

// LecturerFinePolicy: 2.000 VNĐ/cuốn/ngày
public class LecturerFinePolicy implements FinePolicy {
    public double calculateFine(long days, int books) {
        return days <= 0 ? 0 : days * books * 2000.0;
    }
}

Tại sao chọn Strategy Pattern?

  • Đóng với sửa đổi, mở với mở rộng (OCP): Khi thư viện ban hành biểu phí mới cho Nghiên cứu sinh hoặc Cựu sinh viên, chỉ cần tạo class mới implement FinePolicy.
  • Tách bạch logic tính toán: ReturnService không cần biết chi tiết công thức nhân tiền, chỉ gọi policy.calculateFine(...).
  • Kiểm thử độc lập: Dễ dàng viết unit test kiểm tra từng chiến lược tính phạt riêng biệt.

11 Lưu Trữ Bền Vững Với BaseRepository<T>

src/repository/BaseRepository.java 
public abstract class BaseRepository<T extends Serializable> {
    private final String filePath;

    public void saveAll(List<T> items) {
        File file = new File(filePath);
        if (file.getParentFile() != null) file.getParentFile().mkdirs();
        try (ObjectOutputStream oos = new ObjectOutputStream(
                new FileOutputStream(file))) {
            oos.writeObject(items);
        } catch (IOException e) {
            throw new DataStorageException("Lỗi ghi dữ liệu", e);
        }
    }

    @SuppressWarnings("unchecked")
    public List<T> findAll() {
        File file = new File(filePath);
        if (!file.exists()) return new ArrayList<>();
        try (ObjectInputStream ois = new ObjectInputStream(
                new FileInputStream(file))) {
            return (List<T>) ois.readObject();
        } catch (Exception e) {
            throw new DataStorageException("Lỗi đọc dữ liệu", e);
        }
    }
}

Sức mạnh của Java Generics

  • Không lặp mã nguồn (DRY): Toàn bộ 4 kho dữ liệu (accounts.dat, books.dat, readers.dat, tickets.dat) kế thừa trực tiếp saveAll() và findAll().
  • An toàn kiểu biên dịch (Type-Safe): Ràng buộc <T extends Serializable> đảm bảo mọi thực thể lưu xuống đĩa đều hỗ trợ tuần tự hóa.
  • Tự phục hồi thư mục: Tự tạo thư mục data/ nếu chạy trên máy mới chưa có dữ liệu.
